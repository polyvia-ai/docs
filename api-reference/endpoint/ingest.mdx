---
title: "Ingest"
description: "Upload documents and track ingestion status"
---

The Ingest endpoints handle document uploads and status polling. Parsing runs asynchronously — upload returns a `task_id` immediately, which you then poll until ingestion completes.

## Upload Document

Upload a single file for parsing and indexing.

### Endpoint

`POST /api/v1/ingest`

### Request Body

`multipart/form-data`

<ParamField body="file" type="file" required>
  The document to upload. Supported formats: PDF, DOCX, PPTX, XLSX, TXT, MD, and more.
</ParamField>

<ParamField body="name" type="string">
  Display name in your workspace. Defaults to the filename if omitted.
</ParamField>

<ParamField body="group_id" type="string">
  Assign the document to a group on upload.
</ParamField>

### Response

<ResponseField name="document_id" type="string" required>
  Unique identifier for the uploaded document
</ResponseField>

<ResponseField name="task_id" type="string" required>
  Ingestion task identifier — use this to poll for status
</ResponseField>

<ResponseField name="status" type="string">
  Initial status: always `pending`
</ResponseField>

### Example

```bash cURL
curl -X POST https://app.polyvia.ai/api/v1/ingest \
  -H "Authorization: Bearer poly_<your-key>" \
  -F "file=@/path/to/report.pdf" \
  -F "name=Q4 2024 Report" \
  -F "group_id=g_..."
```

<ResponseExample>
```json Success
{
  "document_id": "k57abc123...",
  "task_id":     "3f2e1d0c-...",
  "status":      "pending"
}
```
</ResponseExample>

## Upload Multiple Documents

Upload several files in a single request. Each file is queued as an independent ingestion task.

### Endpoint

`POST /api/v1/ingest/batch`

### Request Body

`multipart/form-data`

<ParamField body="files" type="file[]" required>
  One or more files to upload (repeat the `files` field for each file).
</ParamField>

<ParamField body="names" type="string[]">
  Display names for each file in the same order as `files`. If omitted, filenames are used.
</ParamField>

<ParamField body="group_id" type="string">
  Assign all uploaded documents to this group.
</ParamField>

### Response

<ResponseField name="results" type="array">
  One entry per file, in the same order as `files`.

  <Expandable title="Result object">
    <ResponseField name="document_id" type="string">
      Document identifier
    </ResponseField>
    <ResponseField name="task_id" type="string">
      Ingestion task identifier — poll this to track status
    </ResponseField>
    <ResponseField name="status" type="string">
      Always `pending` on upload
    </ResponseField>
    <ResponseField name="error" type="string | null">
      Present only if this file failed to queue
    </ResponseField>
  </Expandable>
</ResponseField>

### Example

<CodeGroup>
```bash cURL
curl -X POST https://app.polyvia.ai/api/v1/ingest/batch \
  -H "Authorization: Bearer poly_<your-key>" \
  -F "files=@q3.pdf" \
  -F "files=@q4.pdf" \
  -F "names=Q3 Report" \
  -F "names=Q4 Report" \
  -F "group_id=g_..."
```

```python Python SDK
from polyvia import Polyvia

client = Polyvia(api_key="poly_...")

batch = client.ingest.batch(
    ["q3.pdf", "q4.pdf"],
    names=["Q3 Report", "Q4 Report"],
    group_id="g_...",
)
for item in batch:
    client.ingest.wait(item.task_id)
```
</CodeGroup>

<ResponseExample>
```json Success
{
  "results": [
    { "document_id": "k57abc...", "task_id": "3f2e...", "status": "pending", "error": null },
    { "document_id": "k57def...", "task_id": "4a1b...", "status": "pending", "error": null }
  ]
}
```
</ResponseExample>

## Check Ingestion Status

Poll a parse task started by either upload endpoint.

### Endpoint

`GET /api/v1/ingest/{task_id}`

### Path Parameters

<ParamField path="task_id" type="string" required>
  The task identifier returned by `POST /api/v1/ingest` or `POST /api/v1/ingest/batch`
</ParamField>

### Response

<ResponseField name="task_id" type="string">
  Task identifier
</ResponseField>

<ResponseField name="document_id" type="string">
  Document identifier
</ResponseField>

<ResponseField name="status" type="string">
  Processing status (see table below)
</ResponseField>

<ResponseField name="error" type="string | null">
  Error message if status is `failed`, otherwise `null`
</ResponseField>

| `status` value | Meaning |
|----------------|---------|
| `pending`      | Queued, not yet started |
| `parsing`      | Being parsed and indexed |
| `completed`    | Ready to query |
| `failed`       | Parsing failed; see `error` field |

### Example

```bash cURL
curl https://app.polyvia.ai/api/v1/ingest/3f2e1d0c-... \
  -H "Authorization: Bearer poly_<your-key>"
```

<CodeGroup>
```bash Poll until completed
while true; do
  STATUS=$(curl -s \
    -H "Authorization: Bearer poly_<your-key>" \
    "https://app.polyvia.ai/api/v1/ingest/3f2e1d0c-..." \
    | jq -r '.status')
  echo "Status: $STATUS"
  [ "$STATUS" = "completed" ] || [ "$STATUS" = "failed" ] && break
  sleep 5
done
```

```python Python SDK
from polyvia import Polyvia

client = Polyvia(api_key="poly_...")

# Blocks until done — raises IngestionError on failure
done = client.ingest.wait(task_id, poll_interval=5, timeout=300)
```
</CodeGroup>

<ResponseExample>
```json Success
{
  "task_id":     "3f2e1d0c-...",
  "document_id": "k57abc123...",
  "status":      "completed",
  "error":       null
}
```
</ResponseExample>

## Supported File Formats

PDF, DOCX, PPTX, XLSX, TXT, MD, and other common document formats.

<Tip>
Documents are typically processed within 1–2 minutes. Poll the status endpoint every few seconds to check progress.
</Tip>
